تحديث زاد المعرفة — التعديلات الثمانية
تاريخ الإعداد: 25 نوفمبر 2026

هذه حزمة تحديث للنسخة الأصلية zad-almaarefa(2).zip.
تحتوي الملفات الجديدة والمعدّلة فقط، مع الحفاظ على مساراتها داخل المشروع.
ليست مشروعًا كاملًا، ولا تتضمن صفحة كورسات الأستاذة فاطمة المستقلة.

ابدأ من هنا
===========
1) احتفظ بنسخة من مشروعك الحالي، ثم فك محتويات هذه الحزمة داخل مجلد المشروع الكامل، بجوار index.html وpackage.json. وافق على استبدال الملفات المتطابقة بالاسم، وحافظ على المجلدات الموجودة في ZIP.
2) المصدر المعتمد الآن هو الملفات في جذر المشروع ومجلداته. public/ ناتج يُولّد آليًا؛ لا تعدّله يدويًا. لا تحتاج نسخ ملفات المصدر إلى public بنفسك.
3) استخدم Node.js 24، ثم افتح الطرفية داخل المشروع ونفّذ:

   npm run release:check

   يشغّل ذلك الاختبارات وفحص الملفات، ويبني فهرس البحث والجرد الآمن، ويعيد إنشاء public/، ثم يتحقق من تطابقه مع المصدر. أوامر التحقق والبناء تعتمد على أدوات Node المدمجة، ولا تتطلب تنزيل مكتبات npm.
4) public/ غير مرفق في هذه الحزمة لأنه مخرج مولّد يضم بقية المشروع. البناء السابق ينشئه من مشروعك الكامل. الحزمة وحدها لن تعمل كموقع مستقل.

قبل نشر التحديث على الموقع
=========================
بوابة الكتب الجديدة تتحقق من تصنيف المصدر في Firestore. انشر قاعدة libraryMigrationMappings والدالة isLibraryFileOwner المضافتين في firestore.rules قبل نشر البوابة الجديدة.

إذا كانت القواعد الحية تغيّرت بعد نسخة ZIP الأصلية، ادمج الإضافة مع قواعدك الأحدث بدل استبدالها بقواعد أقدم. لا تغيّر قواعد مشروع الخدمات الرقمية المنفصل. لم تُنشر أي قواعد أو تُرفع أي ملفات إلى Firebase أثناء إعداد هذه الحزمة.

صفحة تنظيم المكتبة: dashboard/admin/library-migration.html
تظهر أيضًا في الروابط السريعة للوحة الإدارة وفي صفحة رفع الكتب المحمية.
افتحها بحساب المالك ذي البريد الموثّق، ثم صنّف المصادر واربط المحتوى المدفوع بملفاته المحمية.
الدليل التفصيلي: library-migration-README_AR.md

طريقة النشر حسب الاستضافة
=========================
GitHub Pages:
- في Settings > Pages اجعل Source هو GitHub Actions، حتى يكون النشر من public/ الناتج عن البناء.
- ارفع ملفات التحديث إلى المستودع مع مجلد .github وملف .nvmrc. ملفات المصدر الأصلية غير المعدلة يجب أن تبقى موجودة.
- ملف quality-and-pages.yml يشغّل الفحص عند push وpull request. هذه الأحداث وحدها لا تنشر من هذا الـworkflow.
- بعد نشر قواعد المكتبة ومراجعة التحديث، افتح Actions > Validate and publish Zad > Run workflow من الفرع الافتراضي للمستودع. فعّل خيار publish لتبدأ عملية النشر.
- لا يبدأ النشر إلا بعد نجاح Test, check and build، ويرفع المجلد public/ فقط. اختر GitHub Actions كمصدر للنشر قبل رفع التحديث إذا كان إعدادك القديم ينشر جذر الفرع تلقائيًا.
- GitHub Pages يستضيف الواجهة الثابتة. إعداد خدمة الشات بوت الخلفية القائمة يبقى منفصلًا كما كان.

Vercel:
- أبقِ جذر المشروع Root Directory هو جذر المصدر الذي يحتوي package.json وvercel.json.
- vercel.json أصبح يستخدم npm run release:check للبناء، وpublic للمخرجات الثابتة، مع إبقاء توجيه /api الحالي.
- إعداد Node.js في المشروع أصبح 24.x. لا تُرفع أسرار .env داخل المجلد العام.
- انشر قواعد المكتبة أولًا قبل دفع هذه التغييرات إلى فرع ينشر تلقائيًا.

استضافة ثابتة أخرى:
- نفّذ npm run release:check، ثم انشر محتويات public/ كنشر نظيف يستبدل المخرج السابق.
- لا ترفع جذر المصدر كله بوصفه الموقع العام؛ فيه ملفات تطوير وفهارس خام ونسخ PDF مخصصة للرفع المحمي.
- مجرد إضافة ملفات فوق نشر قديم قد يُبقي الملفات القديمة المنشورة. احذف النسخ العامة القديمة من ملفاتك المدفوعة عند الاستضافة أو استخدم نشرًا نظيفًا كاملًا للمخرج.

تشغيل محلي مع API القائم:
   npm ci
   npm start

يبني npm start النسخة العامة أولًا، ثم يشغّل الخادم المحلي القائم. مفتاح الشات بوت وإعداداته البيئية لم تُضف للحزمة ولم تتغير. غياب المفتاح يؤثر على الشات بوت فقط.

التعديلات الثمانية
==================
1. مصدر واحد للتشغيل والنشر
   أزيل الاعتماد على نسخ public القديمة كمصدر يدوي. البناء يجمع الملفات العامة من المصدر، يستبدل المخرج القديم، ويكتب قائمة تحقق بالمحتويات. المعاينة المحلية تستخدم public نفسه وترفض نسخة لا تطابق المصدر.
   استُبعدت ملفات الخادم، القواعد، ملفات التطوير، الفهارس الخام، وملفات PDF الـ29 المحددة أصلًا في store/local-pdf-migration-manifest.json من النشر. بقيت نسخ المصدر الأصلية متاحة لك للرفع عبر أداة المتجر الموجودة. حُفظ ملف تطبيق الخدمات الرقمية manifest.webmanifest.

2. وضوح القائمة والواجهة
   أربع وجهات أساسية مع قائمة «المزيد»، وكل الروابط السابقة متاحة. حد أدنى مناسب لأزرار اللمس، ونصوص أوضح. ارتفاع شريط الهاتف يُقاس تلقائيًا حتى لا يغطي عنوان المقدمة أو عناوين الأقسام. دُعمت لوحة المفاتيح وEscape واسترجاع التركيز.

3. بحث في المحتوى الحقيقي
   فهرس محلي لعدد 138 نتيجة من ملفات المشروع: 42 كتابًا، 33 ملخصًا، 43 اختبارًا إلكترونيًا أو ورقيًا، 13 تقييمًا، و7 بطاقات معلمين.
   يدعم الكلمات المتعددة والتشكيل والهمزات وأسماء بعض المواد بالإنجليزية، مع فلاتر النوع والصف والمادة. صُححت مادة البحث للكتب ذات العناوين الواضحة بدل الاعتماد على تصنيف عام أو خاطئ في الكتالوج القديم.
   يفتح عبر زر البحث أو Ctrl/Cmd+K. تُحمّل بياناته عند أول فتح. يوجد تحميل إضافي وحالة فارغة وإعادة محاولة عند تعثر الشبكة.
   المنتجات تذهب إلى المنتج المحدد في المتجر، والامتحانات إلى صفحاتها، والملفات القديمة إلى بوابة الوصول. لا يحتوي الفهرس روابط الملفات المدفوعة أو أسئلة الامتحانات وإجاباتها.
   البحث يعكس ملفات المصدر عند آخر بناء؛ المنتجات أو المحتوى الذي ينشأ فقط داخل قاعدة البيانات لا ينضم آليًا إلى هذا الفهرس قبل تحديث مصدره وإعادة البناء. الإتاحة الحالية تُراجع في صفحة المحتوى أو المتجر.

4. تقدم الطالب من سجلات حسابه
   استُبدلت نسب localStorage بملخص حضور الأسبوع، وآخر نتيجة معتمدة، وآخر حصة سجلت الإدارة حضوره فيها.
   الأسبوع يبدأ السبت وينتهي الجمعة بتوقيت القاهرة. القراءة مقيدة بمعرّف الطالب، وتُستبعد النتائج غير المعتمدة والسجلات المحذوفة والحضور المستقبلي. فتح كتاب أو رابط ليس إكمالًا أو حضورًا.
   عند فشل القراءة يظهر الخطأ بوضوح بدل قيمة صفر مضللة. الاستجابات القديمة لا تظهر بعد تبديل الحساب، والبيانات الإضافية للفهرس لا تعلق التحميل بلا مهلة.

5. تنقل لوحة الطالب ورسائلها
   التبويبات تدعم ?tab=notifications وروابط الملف الشخصي القديمة، والتحديث والرجوع والتقدم في المتصفح. التبويب المجهول يعود إلى النظرة العامة. تحسنت رسائل الأعطال وإعادة المحاولة، واستُبعدت التفاصيل الفنية من الرسائل الموجهة للطالب.

6. تخفيف الصفحات الثقيلة
   استُخرجت 14 صورة مضمّنة مكررة من أربع صفحات إلى ملف JPEG مشترك مطابق للصورة الأصلية، مع فك ترميز غير متزامن. حُفظ التحميل الكسول للصور المناسبة في الصفحة الرئيسية، وبقيت صورة المقدمة ذات أولوية عالية.
   أحجام HTML للصفحات الأربع كانت 6,782,660 بايت؛ أصبحت 188,274 بايت. مع الصورة المشتركة 241,805 بايت يصبح الإجمالي 430,079 بايت، أي انخفاض يقارب 93.7% في حجم هذه الملفات. هذا قياس لحجم الملفات، وليس ادعاءً بنسبة تسريع تحميل الموقع كله.

7. تنظيم المصادر القديمة وتوصيلها بالحماية القائمة
   أداة للمالك لتصنيف 102 هوية مصدر فريدة من 105 سجلات محلية، وربطها بكتب محمية أو رفع PDF مناسب، دون جعل الكتب مدفوعة تلقائيًا.
   الجرد المنشور بيانات وصفية وهويات فقط. يمكن للمالك قراءة الكتالوج من جهازه دون رفع نصوصه أو روابطه الخام. التصنيفات المحمية لا تحتوي رابط تنزيل عامًا.
   بوابة الوصول تتوقف عند فشل قراءة التصنيف، ولا ترجع للرابط القديم بعد ربطه بكتاب محمي. ربط التخزين يستخدم سياسة المالك الموثّق الموجودة؛ لا يوسّع حقوق بقية الإداريين.
   بحث API وسياق الشات بوت أصبحا بيانات وصفية وروابط بوابات فقط، دون مقتطفات من نصوص الملخصات أو روابط مصادرها الخاصة.
   نقل الملفات وتقييد مشاركة Google Drive أو أي مصدر خارجي يحتاجان إجراءً من مالك المصدر. لم تُبطل روابط خارجية ولم تُرفع ملفات حية بهذه الحزمة. اشتراكات المكتبة لا تُخلط بمشتريات المتجر؛ أداة المتجر القائمة تظل المسار لملفات المنتجات الـ29.

8. اختبارات وفحص قبل النشر
   npm test يشغّل الاختبارات الفعلية. صُححت الاختبارات القديمة التي كانت تفترض مواضع كود لم تعد مستخدمة، واستُبدلت باختبارات تشغّل المنطق الحالي محليًا.
   npm run check يفحص تركيب JavaScript والسكربتات داخل HTML ومراجع الأصول المرتبطة بالتحديث.
   npm run build ينشئ public من المصدر وفهارسه الآمنة، وnpm run verify:build يتحقق من التطابق وعدم بقاء ملفات إضافية قديمة.
   npm run release:check يجمع الخطوات كلها، وتستخدمه إعدادات Vercel وGitHub Actions المرفقة. يفشل النشر عبرهما إذا فشل الفحص.

حدود التحقق
===========
نجح 80 اختبارًا محليًا. فُحص تركيب 158 ملف JavaScript و34 سكربتًا داخل HTML و137 مرجعًا للأصول. طابق البناء 300 ملف عام مع مصدره.

التحقق محلي على نسخة المشروع: اختبارات المنطق، فحص ملفات الكود، تطابق المخرج، ومراجعة بصرية وتفاعلية للصفحة الرئيسية والبحث والقائمة على أحجام هاتف ولوحي وحاسوب.
لم يُنفذ تسجيل دخول بحسابات حقيقية، أو دفع، أو نشر قواعد Firebase، أو رفع PDF إلى Storage، أو نشر هذا التحديث إلى موقعك. اختبارات بوابة الملفات تستعمل بدائل محلية للخدمات؛ ليست بديلًا عن تجربة حساب مشترك وغير مشترك في بيئتك بعد التفعيل.

راجع UPDATE_MANIFEST.json لمعرفة كل ملف جديد أو معدّل وبصمته مقارنة بالأرشيف الأصلي. public/ غير مدرج لأنه يعاد توليده. لا تحتوي الحزمة أي حذف من ملفات المصدر الأصلية.
