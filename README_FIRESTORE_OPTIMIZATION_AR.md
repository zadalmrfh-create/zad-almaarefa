# تحسين استهلاك Firestore — زاد المعرفة

## التغيير المنفذ
- أُضيفت وحدة مشتركة `dashboard/admin/firestore-read-cache.js` لتجميع طلبات قراءة المجموعة نفسها بين وحدات لوحة الإدارة.
- تُشارك الوحدات الأربع عشرة نتيجة القراءة نفسها أثناء الطلب المتزامن، مع إعادة استخدام قصيرة لا تتجاوز 8 ثوانٍ.
- استعلامات الطلاب/المدفوعات المحددة بـ `query()` لا تدخل في التخزين المؤقت حتى لا تتأخر البيانات المالية الخاصة.
- تُمسح الذاكرة المؤقتة عند إشعارات تعديل الحضور واعتماد الدفع وتعديل المستخدمين.
- زر تحديث الحضور يطلب بيانات جديدة بدل استخدام الذاكرة المؤقتة.

## حدود الإصلاح
- هذا تحسين أولي واسع النطاق للوحة الإدارة وليس ضمانًا لإصلاح كل مصادر استهلاك Firestore في الموقع.
- لا يعيد ضبط حصص Firebase المجانية، ولا يحل خطأ resource-exhausted إذا انتهت حصة القراءات اليومية.
- لا يغير قواعد Firestore أو المدفوعات أو سجلات الحضور، ولا يثبت نجاح حذف الحصص دون تجربة فعلية.
- يُنصح بقياس Reads بعد نشر النسخة ومراجعة أكثر الأقسام استهلاكًا، ثم تحسين الاستعلامات والصفحات تباعًا.
