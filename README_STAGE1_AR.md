# تحديث المرحلة الأولى — منصة زاد المعرفة

**تاريخ الإعداد:** 14 نوفمبر 2026  
**نوع الحزمة:** ملفات تعديل فقط، وليست نسخة جديدة من المنصة.  
**المصدر:** الفرع `main` في `zadalmrfh-create/zad-almaarefa` بعد التحقق من تطابق `dashboard/student/index.html` وقواعد `firestore.rules` مع النسخة الموجودة وقت الإعداد.

## ما تم تعديله

1. **تسجيل فتح Google Meet:** كان زر الدخول يحاول إضافة مستند إلى `lessonAttendance` التي تمنع قواعدها إضافة الطالب للسجل؛ الآن يفتح Meet من دون انتظار Firebase، ويحاول تسجيل فتح الرابط في `lessonOpenEvents` منفصلة ومحكومة الصلاحيات. يسجل النظام محاولة فتح واحدة لكل طالب ومحاضرة ولا يحولها إلى حضور رسمي. يظل الحضور والغياب خاضعين لإدارة المنصة.
2. **منع تكرار تقييم النجوم السريع:** بدل مستند بمعرّف عشوائي، يُحفَظ التقييم في `lessonRatings/{studentUid}__{lessonId}`، مرة واحدة فقط من الطالب. يعرض الزر بعد الإرسال «✅ تم إرسال التقييم»، حتى بعد إعادة تحميل الصفحة. الطالب الذي قيّم سابقًا بمعرّف عشوائي تكتشف الصفحة تقييمه القديم من استعلام محدود بحسابه ولا تطلب منه إرسال آخر.
3. **صلاحيات Firestore:** السماح بقراءة تقييم الطالب نفسه فقط، وإنشاء تقييم جديد بمعرّف ثابت، والسماح بإنشاء حدث فتح Meet واحد غير قابل للتعديل؛ مع الاحتفاظ بصلاحيات الأدمن في السجلات الرسمية.
4. **فحص تعارض صفحات الموقع:** إضافة فحص يتحقق من ملفات الدخول الأساسية ومراجع سكريبتات الأدمن، وينبه إلى وجود نسختين مختلفتين داخل `public/` و`dashboard/`. مصدر GitHub Pages المعتمد في هذا التعديل هو **جذر المستودع** (`main`, `/(root)`)، وليس `public/`.
5. **اختبارات تلقائية:** ستة اختبارات للمعرّفات وحالات التكرار وقواعد التسجيل والتقييم الشهري، وفحص صياغة وحدات JavaScript. ملف GitHub Actions لتشغيلها عند تحديث الملفات المعنية.

## التركيب

1. انسخ احتياطيًا الملفين الحاليين `dashboard/student/index.html` و`firestore.rules` من المستودع أو احتفظ برقم الـ commit السابق.
2. **ارفع محتويات الحزمة بعد فك الضغط إلى جذر المستودع**، محافظًا على المجلدات كما هي؛ لا ترفع ZIP مباشرة، ولا تضع مجلد `dashboard` داخل مجلد `dashboard` آخر.
3. اضغط **Commit changes** وتحقق من نجاح GitHub Actions باسم `Zad - Prepublish checks`، ثم اكتمال نشر GitHub Pages.
4. افتح **Firebase Console → Firestore Database → Rules** والصق محتوى `firestore.rules` **كاملًا** واضغط **Publish**. مجرد رفع الملف إلى GitHub لا يطبق القواعد على قاعدة بياناتك.
5. افتح صفحة الطالب بتحديث قوي `Ctrl + Shift + R`. اختبر بحساب طالب تجريبي له محاضرة منشورة.

## خطوات اختبار يدوي (يلزم تنفيذها على Firebase الفعلي)

- افتح محاضرة من حساب طالب. يجب فتح Meet فورًا دون شاشة انتظار طويلة. ادخل **Firestore → `lessonOpenEvents`** وتحقق من ظهور حدث واحد بالمُعرّف `{UID}__{lessonId}`.
- اضغط زر الدخول مرة ثانية، ويجب ألا يسجل حدثًا ثانيًا. **هذا الحدث ليس إثبات حضور** ولا يغيّر كشف الحضور/الغياب الرسمي.
- قيّم محاضرة تقييمًا سريعًا 1–5. يجب ظهور «تم إرسال التقييم» وتعطيل الزر. حدّث الصفحة وجرب الجهاز الآخر لنفس الحساب؛ يجب أن يبقى التقييم مسجلًا.
- اختبر طالبًا سبق أن قيّم قبل التعديل؛ ينبغي عدم طلب نفس التقييم مجددًا عند العثور على سجله القديم.
- تحقّق من استمرار **التقييمات الأسبوعية للمعلمين** و**الشهرية للمنصة والإدارة**، وزر مشاركة تقييمات المحاضرات، ونتائج الامتحانات من لوحة الأدمن؛ لم تُستبدل ملفات تلك الأقسام في الحزمة.
- جرّب حالتي انقطاع الإنترنت وعدم نشر القواعد. لن يجب أن تُعلن الواجهة «تم إرسال التقييم» إلا بعد التأكد من الحفظ. فتح Meet لا يتوقف على نجاح كتابة سجل الفتح.

## تشغيل الاختبارات محليًا

من داخل المجلد الرئيسي للمشروع مع Node.js 22:

```bash
node scripts/check-stage1.mjs
node --test tests/stage1.test.mjs
```

**حدود التحقق:** اختبارات الكود والفحوصات المحلية نجحت أثناء تجهيز الحزمة. لم يُنشَر هذا التعديل على حسابك في GitHub أو Firebase، ولم تُختبر قواعد Firestore على Emulator أو على بيانات الطلاب الحقيقية. يجب تجربة مستخدم حقيقي تجريبي بعد النشر قبل تعميمه.

## مصدر النشر والتراجع عن التغيير

- GitHub Pages للمشروع: `https://zadalmrfh-create.github.io/zad-almaarefa/`، ومنه صفحة الأدمن `dashboard/admin/index.html`. لو إعداد Pages ليس `main/(root)`، تحقّق منه قبل النشر.
- يوجد مجلد `public/` قد يحتوي على صفحات قديمة لبيئة نشر أخرى؛ **لم نحذفه ولم ننشر فوقه** حتى لا تتعطل بيئة نشر مستقلة مثل Vercel. الفحص الجديد يعطي تحذيرًا لو نسخة الأدمن فيه مختلفة.
- عند التراجع، استعد **ملفي لوحة الطالب وقواعد Firestore معًا** من commit سابق، وأزل ملفات الاختبارات الجديدة من نفس التحديث عند الحاجة. لا تحذف بيانات Firebase الخاصة بالتقييمات أو الحضور تلقائيًا.
